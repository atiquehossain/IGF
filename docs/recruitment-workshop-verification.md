## Open release and deployment gates

The code is a locally verified release candidate. Production deployment and the phrase “production-ready” still require the target owner to execute and approve all of these target-specific checks:

- verify the target web-SAPI—not only CLI PHP—loads `sodium`, `fileinfo`, `iconv`, and `zlib`, and can launch the bounded PDF worker;
- verify private storage ACLs and confirm neither private disk is web/CDN/object-ACL accessible;
- approve TLS, trusted-proxy, cookie, WAF/reverse-proxy, and effective PHP/proxy body limits;
- take and restore a coupled target database/private-file backup, reconcile cleanup-outbox and document/import checksums, and record the restore drill;
- rerun genuine final-seat/waitlist concurrency against the target database topology or an owner-approved topology-equivalent staging environment;
- complete target smoke checks and obtain explicit owner launch approval.
